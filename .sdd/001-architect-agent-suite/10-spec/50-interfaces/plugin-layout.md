# C001-IF-08 — Plugin layout, manifests and structure checks

## §1 Repository and plugin tree

```text
<repo>/
├── .claude-plugin/marketplace.json        local marketplace (C001-REQ-1102)
├── plugins/architect/                     the plugin root (${CLAUDE_PLUGIN_ROOT})
│   ├── .claude-plugin/plugin.json
│   ├── agents/sdd-*.md                    10 agents (C001-IF-09)
│   ├── skills/<name>/SKILL.md (+ references/)
│   ├── commands/*.md                      /architect:* (C001-IF-10)
│   ├── hooks/hooks.json                   (C001-IF-07)
│   ├── .mcp.json                          context7, deepwiki, serena (C001-REQ-1108)
│   ├── serena/architect-read-only.yml     Serena read-only mode file (C001-REQ-1006, C001-IF-14 §4)
│   ├── scripts/sdd.mjs                    bundled CLI (generated by the build)
│   ├── templates/                         artifact templates (full and lite)
│   ├── LICENSE, README.md, THIRD_PARTY_NOTICES.md
├── src/                                   CLI sources (bundled into scripts/sdd.mjs)
├── tests/                                 unit tests, lint fixtures, guard corpus, secrets fixtures
├── evals/                                 delegation and injection eval suites
├── bench/                                 NFR benchmarks
├── .github/workflows/check.yml            dormant matrix (C001-REQ-1119)
├── package.json                           scripts: build, test, check; devDependencies only
├── LICENSE, README.md                     (repository copies or links)
└── .sdd/                                  this project's own SDD workspace
```

Placing the plugin under `plugins/architect/` keeps development files (sources, tests,
`.sdd/`) out of the installed plugin.

## §2 Manifests

`plugins/architect/.claude-plugin/plugin.json`:

```json
{ "name": "architect", "version": "0.1.0", "description": "Spec-driven development agents: ideation → specification → planning with gates", "license": "MIT", "author": { "name": "<copyright holder>" } }
```

`.claude-plugin/marketplace.json` (repository root):

```json
{ "name": "architect-local", "owner": { "name": "<copyright holder>" }, "plugins": [ { "name": "architect", "source": "./plugins/architect", "description": "Spec-driven development agent suite" } ] }
```

Field names confirmed with `claude plugin validate` in spike S-05 (Claude Code 2.1.295): required are
the plugin `name` (kebab-case) and, for the marketplace, `name`, `owner` and `plugins[].source`
starting with `./`; `version`, `description`, `author` and the marketplace `metadata.description`
are recommended. `claude plugin validate` stays authoritative (C001-REQ-1117).

## §4 Template access

Agent, command and skill bodies name a template as `sdd template show <profile>/<path>` and list
the templates of a profile with `sdd template list <profile>` (C002-IF-007; C002-REQ-513,
C002-REQ-520), on Claude Code as on the generated targets (C002-REQ-115). `<profile>` is the
change's profile in `change.md` (`full` or `lite`) or `constitution`, and a body names the whole
argument, for example `sdd template show lite/10-spec/spec.md`. No body names a path under
`${CLAUDE_PLUGIN_ROOT}/templates/` for Read, Glob or Grep:

- The plugin root lies outside the session's working directory, so Claude Code asks for
  permission on each such read, and the plugin cannot grant it: plugin agents ignore
  `permissionMode` (C001-CON-03), and the guards of C001-IF-07 only deny.
- A direct read skips the repository override in `.sdd/_templates/<profile>/`, which
  `sdd template show` applies (C002-REQ-513; C001-COMP-13).

`sdd` runs through the Bash tool (C001-IF-07 §3, sdd CLI entry), so reading a template needs no
permission beyond the one every `sdd` command already needs.

Origin: defect D-019 item 2, the C001-TS-213 trace of `t082-d018`: the spec-writer's Glob, Read
and Grep under the plugin root were refused (102–131 s), then it tried `sdd template` forms
until one worked and read five full-profile templates before the lite one (134–220 s); P-01
Q-t082-bugs-01 "Fix all 3 now (Recommended)".
